# «Зацеп» — сайт-презентатор и бронирование детского скалолазания

> Рабочее название. Детские (в том числе инклюзивные) занятия по скалолазанию: презентация,
> локации, галерея, лента новостей, бронирование слотов, уведомления в Viber.

Интерактивный прототип дизайна: [`concept.html`](./concept.html) — открыть в браузере.

---

## 1. Роли

| Роль | Что может |
|---|---|
| **Гость** | Смотреть сайт, расписание, локации, галерею, ленту; начать бронь (с регистрацией в 1 шаг по телефону) |
| **Родитель (юзер)** | Профили детей, бронь/отмена/частичное освобождение мест, история броней, подключение личного Viber, настройки уведомлений |
| **Тренер** | Видит свои занятия и списки детей с пометками об особенностях, отмечает посещаемость |
| **Админ** | Всё: события, расписание на месяц, рабочее время, шаг слотов, вместимость, локации, галерея, новости, фон, уведомления, отчёты |

## 2. Стек

Бэкенд переиспользует то, что уже есть в этом репозитории (FastAPI + Celery + PostgreSQL + Redis) —
этот набор идеально ложится на бронь и асинхронные уведомления.

| Слой | Выбор | Зачем |
|---|---|---|
| API | **FastAPI**, SQLAlchemy 2 async, **Alembic** (вместо `create_all`) | Уже знакомо; миграции обязательны для живых данных |
| Очереди | **Celery + Redis** (+ celery beat) | Отправка в Viber, напоминания, ретраи, авто-освобождение |
| БД | **PostgreSQL** | `EXCLUDE`/`CHECK`-ограничения и `SELECT … FOR UPDATE` против двойной брони |
| Realtime | WebSocket / SSE через Redis pub/sub | Слоты «тают» на глазах у всех, когда кто-то бронирует |
| Фронт | **Next.js (App Router)** + TypeScript | SSR/SEO для презентационной части, SPA для кабинета/админки |
| Анимации | **GSAP** (+ScrollTrigger), **Motion**, **Lenis** (плавный скролл), **Rive** для руки-курсора и маскота | Живой, «физичный» интерфейс |
| Календарь админа | FullCalendar (resource/timeGrid) с кастомной темой | Drag-and-drop расписания |
| Файлы | S3-совместимое (MinIO локально / Cloudflare R2), resize через imgproxy | Галерея и фоновые фото |
| Деплой | Docker Compose → VPS, Caddy (HTTPS), бэкапы Postgres | Дёшево и надёжно |

## 3. Модель данных (ядро)

```
users(id, phone*, email, name, password_hash, role, locale, created_at)
children(id, user_id→users, name, birth_date, needs_flags[], needs_note, photo_consent, medical_consent)
locations(id, name, address, geo, photos[], description, how_to_get, wall_info, accessibility)
instructors(id, user_id, bio, photo, specializations[])

event_types(id, title, description, age_min, age_max, inclusive, color, hold_shape, price, duration_min)
working_hours(id, location_id, weekday, opens, closes)            -- регулярное рабочее время
schedule_exceptions(id, location_id, date, opens?, closes?, closed)  -- праздники/выходные/переносы
slot_rules(id, location_id, event_type_id?, step_min, capacity, valid_from, valid_to)
                                                                  -- «бронь каждые 30 мин, 6 мест»
events(id, event_type_id, location_id, instructor_id, starts_at, ends_at, capacity,
       recurrence_rule?, parent_event_id?, status, notify_on_create, notify_on_change,
       booking_opens_at, cancel_deadline_min, created_by)
bookings(id, event_id, user_id, seats, status[active|cancelled|released|attended|no_show],
         created_at, updated_at)
booking_children(booking_id, child_id)
booking_log(id, booking_id, actor_id, action[create|add_seats|release|cancel|admin_edit], delta, at)

waitlist(id, event_id, user_id, seats, position, notified_at)

viber_links(user_id, viber_user_id, subscribed, linked_at)
notification_prefs(user_id, kind, channel, enabled)
notification_outbox(id, kind, payload, target, status, attempts, sent_at)   -- transactional outbox

news_posts(id, title, body, cover, event_id?, pinned, published_at, auto_generated)
gallery_albums(id, title, location_id?, event_id?, cover) / gallery_photos(id, album_id, url, w, h, blurhash)
site_settings(key, value)   -- фон главной, контакты, тексты, включатели фич
```

**Ключевые инварианты**
- Сумма `seats` активных броней на событие ≤ `capacity` — проверка в транзакции с
  `SELECT … FOR UPDATE` на строку события (или счётчик `seats_taken` с `CHECK`).
- Каждое изменение брони пишется в `booking_log` — из него строятся и уведомления, и отчёты «кто сколько».
- Уведомления пишутся в `notification_outbox` **в той же транзакции**, что и бронь; Celery
  отправляет и ретраит — ни одно сообщение не теряется и не уходит при откате.

## 4. Логика бронирования

1. **Генерация слотов.** Из `working_hours` − `schedule_exceptions` + `slot_rules` строим сетку
   (например 10:00–18:00, шаг 30 мин, по 6 мест). Админ может «материализовать» сетку в события
   на месяц одной кнопкой или создавать события вручную.
2. **Бронь.** Выбрать слот → сколько мест / каких детей → подтвердить. Мест не хватает — предложить лист ожидания.
3. **Изменения.**
   - *Отменить* — бронь целиком;
   - *Освободить* — уменьшить число мест (было 3, стало 1);
   - *Добавить* места — если есть свободные.
   Действия доступны до `cancel_deadline_min` до начала, после — только через админа.
4. **Лист ожидания.** Освободилось место → первому в очереди уходит сообщение, у него 15–30 мин
   подтвердить, иначе место уходит следующему.
5. **Повторяющиеся события** (RRULE): «каждый вторник 17:00 до конца месяца»; правка одного или всей серии.
6. **Защита от злоупотреблений:** лимит активных броней на юзера, учёт no-show, rate limit
   (уже есть в репо `rate_limiter.py`).

## 5. Уведомления в Viber

### Что отправляется
| Событие | В группу/канал | Лично юзеру |
|---|---|---|
| Админ создал событие (если `notify_on_create`) | ✅ «Новое занятие: Вт 15.10, 17:00, Скалодром «Север», 6 мест» | ✅ подписанным |
| Бронь создана | ✅ «Анна забронировала 2 места на Вт 17:00 (осталось 3)» | ✅ подтверждение |
| Места освобождены | ✅ «Игорь освободил 1 место — Вт 17:00 (свободно 2)» | ✅ |
| Бронь отменена | ✅ «Бронь Марии на Ср 11:30 отменена» | ✅ |
| Событие изменено/отменено админом | ✅ | ✅ всем записанным |
| Напоминание за 24 ч / 2 ч | — | ✅ |
| Освободилось место из листа ожидания | — | ✅ с кнопкой «Забрать» |

Админ на каждом событии выбирает: уведомлять ли группу, уведомлять ли записанных, тихий режим
(без уведомлений ночью — сообщения копятся и уходят утром). В группе показываем имя в коротком
виде («Анна К.») — приватность.

### Как технически
- **Личные уведомления:** Viber Bot (REST API `chatapi.viber.com`, вебхук на FastAPI).
  Привязка: в кабинете кнопка «Подключить Viber» → deep-link
  `viber://pa?chatURI=<bot>&context=<одноразовый токен>` → бот получает `conversation_started`
  с токеном и `viber_user_id` → связываем с аккаунтом. Плюс кнопки в сообщениях
  («Отменить бронь», «Мои брони»).
- **Групповые уведомления:** боты Viber не могут писать в обычные группы/сообщества.
  Рабочий вариант — **Viber-канал** и его **Channels Post API** (токен канала, публикация от имени канала).
  Родителей приглашаем в канал; обсуждение можно оставить в отдельном сообществе.
- **Важный риск:** с 2024 года новые Viber-боты создаются только на коммерческих условиях
  (через партнёров, платно). Поэтому канал отправки делаем абстракцией `Notifier`
  (`ViberChannelNotifier`, `ViberBotNotifier`, `TelegramNotifier`, `EmailNotifier`, `WebPushNotifier`) —
  можно стартовать с Viber-канала + web push/Telegram и подключить бота, когда он будет оплачен.

## 6. Админка

- **Месячный календарь** (вид месяц/неделя/день, фильтр по локации и тренеру): drag-and-drop переноса,
  растягивание длительности, копирование недели на следующую, массовая отмена дня.
- **Рабочее время** по локациям и дням недели + исключения (праздники).
- **Правила слотов:** шаг (15/30/45/60 мин), длительность занятия, вместимость, когда открывается запись
  («за 14 дней»), дедлайн отмены.
- **Конструктор события:** тип, локация, тренер, время, места, повтор, «уведомлять: группа / записанные / никого»,
  «создать новость в ленте автоматически».
- **Списки:** кто и сколько забронировал на событие, с особенностями детей (видно только админу/тренеру),
  ручное добавление/удаление, отметка посещаемости, экспорт CSV/печать.
- **Журнал действий** (`booking_log` + действия админов).
- **Контент:** галерея (drag-drop загрузка, альбомы), новости, локации, фон главной, тексты.
- **Дашборд:** заполняемость по дням/слотам, отмены, no-show, новые семьи.

## 7. Кабинет пользователя

## 8. Дизайн-концепция «Стена»

Цель — интерфейс, который ощущается как скалодром, а не как шаблон.

**Идея:** весь сайт — это скалолазная стена. Пользователь «лезет» вниз по странице.

- **Кнопки = зацепки.** Каждая кнопка — SVG-зацепка своей формы (jug, crimp, sloper, pinch, volume),
  с отверстием под болт. Цвет зацепки = «трасса» (у каждого типа занятия свой цвет, как маркировка трасс).
  Hover — зацепка слегка покачивается на болте; нажатие — «прожимается» с магнезиальной пылью (частицы).
- **Курсор = рука.** Открытая ладонь, над кликабельным — тянется пальцами, при нажатии сжимается в хват
  (Rive state machine: idle → reach → grab). На тач-устройствах — отпечаток магнезии в точке касания.
- **Скролл-«маршрут».** Сбоку по странице идёт верёвка; маленький скалолаз-маскот (Rive) поднимается по ней
  по мере скролла (ScrollTrigger). Конец страницы — «топ», звонок-колокольчик.
- **Расписание = стена со слотами.** Дни — колонки-панели фанеры с текстурой, слоты — зацепки.
  Заполненность показывается количеством «следов магнезии». Забронированный слот — зацепка с лентой-оттяжкой.
- **Фон — своё фото.** Админ ставит фон главной (и сезонные фоны); юзер может выбрать фон кабинета.
  Поверх — зернистость (grain) и дуотон в фирменных цветах, чтобы любое фото выглядело «в стиле».
- **Новостная лента** — «доска объявлений скалодрома»: карточки прижаты зацепками/карабинами,
  чуть повернуты, при наведении выпрямляются.
- **Галерея** — фото как на стене; клик — фото «срывается» и раскрывается на весь экран.
- **Типографика:** крупный гротеск с характером (Unbounded / Dela Gothic One для заголовков,
  Manrope / Golos для текста — хорошо с кириллицей), рукописные пометки (Caveat) как маркером на стене.
- **Палитра:** тёплая фанера `#E8D9BF`, графит `#1E1D1B`, цвета трасс — неоновые, но не кислотные:
  `#FF5A36` (оранжевая), `#2BB3A3` (бирюза), `#FFC23D` (жёлтая), `#7B5CFF` (фиолетовая), `#FF7FB0` (розовая).
- **Микрозвуки** (выключены по умолчанию): щелчок карабина при брони, шорох магнезии.

**Доступность — обязательна** (среди аудитории дети с особенностями и их родители):
переключатель «Спокойный режим» (отключает анимации, кастомный курсор и звуки, повышает контраст),
уважение `prefers-reduced-motion`, вся навигация с клавиатуры, видимый фокус, крупные цели нажатия,
ARIA-метки у зацепок (это обычные `<button>`, форма — только визуал), простой язык, версия
«социальная история» для детей с РАС (картинками: что будет на занятии шаг за шагом).

## 9. Предлагаемый дополнительный функционал

**Для родителей и детей**
1. **Лист ожидания** с авто-предложением освободившегося места.
2. **Абонементы и онлайн-оплата** (LiqPay / Monobank / Stripe), пакеты «8 занятий», семейные скидки, сертификаты в подарок.
3. **Напоминания** за 24 ч и 2 ч + «Буду / не смогу» прямо в Viber.
4. **Профиль особенностей ребёнка** для тренера: триггеры, что успокаивает, нужен ли сопровождающий —
   тренер видит перед занятием.
5. **«Социальная история» / визуальное расписание** занятия для детей с РАС.
6. **Прогресс ребёнка:** пройденные трассы, бейджи («Первый топ», «10 занятий»), сертификат-уровень —
   мотивация и отличный повод для родителя поделиться.
7. **Фото с занятия** — приватные альбомы, видимые только родителям участников.
8. **Электронный отказ от претензий / согласие** с подписью пальцем при первой брони.
9. **Друзья:** забронировать рядом с другом («в одну группу с Мишей»).
10. **Добавить в календарь** (.ics, Google Calendar), карта и маршрут до локации.

**Для админа и бизнеса**
11. **Посещаемость и no-show** со штрафной логикой (после N неявок — бронь только с предоплатой).
12. **Аналитика** заполняемости, тепловая карта популярных слотов — подсказывает, где добавить группы.
13. **Шаблоны недели** и копирование расписания на месяц одним кликом.
14. **Автоновости:** создал событие → черновик поста в ленте и в Viber-канале.
15. **Отзывы** после занятия (1 вопрос в Viber) → лучшие на главную.
16. **Мультиязычность** (UA/RU/EN).
17. **PWA:** установка на телефон, web-push как запасной канал уведомлений.
18. **Telegram-бот** как второй канал (бесплатный, умеет писать в группы).
19. **Погода** для уличных локаций и авто-предупреждение при переносе.
20. **Роли тренеров** с их личным расписанием и отметкой посещаемости с телефона.

## 12. Риски и решения

| Риск | Решение |
|---|---|
| Viber-бот платный / нельзя писать в группы | Канал + Channels Post API; абстракция `Notifier`; Telegram/web-push как запасные |
| Двойная бронь при одновременных запросах | Транзакция + `FOR UPDATE`, `CHECK seats_taken <= capacity`, идемпотентный ключ запроса |
| Тяжёлые анимации тормозят на слабых телефонах | Анимации только `transform/opacity`, ленивая загрузка Rive, авто-«спокойный режим» при низком FPS |
| Персональные данные детей (особенности, здоровье) | Отдельная таблица с шифрованием полей, доступ только админ/тренер, согласия, удаление по запросу |
| Кастомный курсор мешает части пользователей | Отключаемый, не на тач-устройствах, системный курсор при `prefers-reduced-motion` |
